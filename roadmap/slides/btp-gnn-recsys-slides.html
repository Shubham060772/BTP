Phase 2

Matrix Factorization

Week 1–2 — The critical baseline for your BTP

Core Idea

\( R \approx U V^T \)

R = Rating matrix
(users × items)

U = User embeddings
(users × d)

V = Item embeddings
(items × d)


\( \hat{R}_{ui} = \mathbf{u}_i^T \mathbf{v}_j \)

Predicted rating = dot product of user & item embeddings

Visually

items → ┌─────────────────┐ │ │ users → │ R │ ≈ U × VT │ (sparse) │ │ │ (n×d) (d×m) └─────────────────┘ (n × m)

Each user and item gets a d-dimensional embedding.
The dot product of these embeddings predicts the interaction.

Why MF Matters for Your BTP

  • It's the strongest non-graph baseline
  • Same core idea as GNN: learn embeddings, compute scores
  • GNNs extend MF by using graph structure during embedding learning
  • If your GNN can't beat MF → your graph isn't helping

Implement MF in PyTorch — you'll reuse this code structure for GNN models.

Adjacency Matrix

A B C A [ 0 1 1 ] B [ 1 0 0 ] C [ 1 0 0 ]

Bipartite Graph — The Key Concept

Users Items User 1 ─────────── Movie A │ └──────────────── Movie C User 2 ─────────── Movie A │ └──────────────── Movie B User 3 ─────────── Movie B

Two disjoint sets of nodes. Edges only go between sets, never within.

Formal Definition

\( G = (U, I, E) \)

\(U\) = set of user nodes

\(I\) = set of item nodes

\(E\) = set of interaction edges


Your entire recommendation system lives on this graph.

Why Graph > Matrix?

  • Multi-hop connections — U1 and U2 share Movie A → they're similar
  • Transitive structure — paths through the graph encode latent similarity
  • Extensibility — add genre nodes, actor nodes, social edges…
  • GNNs can learn from this structural information

Phase 4–6

GNN Core Concepts

Week 3–4 — Message Passing, GCN, GraphSAGE, GAT

Message Passing Intuition

How can a user's representation be influenced by the items they interacted with?

Movie 1 ──→ User A Movie 2 ──→ User A │ ▼ Updated User A representation │ ▼ recommend → Movie 3

Each node collects messages from its neighbors and updates its representation.

Message Passing Framework

For each node: 1. MESSAGE — neighbors send their features │ ▼ 2. AGGREGATE — combine neighbor messages (sum, mean, max, attention) │ ▼ 3. UPDATE — transform to get new node features │ ▼ Repeat for L layers

After L layers, each node's representation captures its L-hop neighborhood.

GCN — Graph Convolutional Network

\( H^{(l+1)} = \sigma \left( \hat{D}^{-1/2} \hat{A} \hat{D}^{-1/2} H^{(l)} W^{(l)} \right) \)

\(\hat{A}\) = adjacency matrix + self-loops

\(\hat{D}\) = degree matrix of \(\hat{A}\)

\(H^{(l)}\) = node features at layer \(l\)

\(W^{(l)}\) = learnable weight matrix

\(\sigma\) = activation (ReLU)

GCN Simplified

Node features │ ▼ Neighbor aggregation (normalized sum of neighbor features) │ ▼ Linear transform (multiply by W) │ ▼ Activation (ReLU) │ ▼ Updated representation │ Repeat L times

GraphSAGE

Key idea: Sample a fixed number of neighbors

All neighbors → Sample K neighbors → Aggregate → Update

Why useful?

  • Scales to large graphs (fixed computation per node)
  • Inductive — can handle unseen nodes
  • Multiple aggregators: mean, LSTM, pooling

GAT — Graph Attention Network

Key idea: Not all neighbors are equally important

For node i and neighbor j: attention weight αij = softmax( LeakyReLU( aT[Whi ∥ Whj] ) ) new features h'i = σ( Σj αij · W hj )

Learns which neighbors matter most via attention coefficients.

You don't need to master all three. Learn them for comparison — your BTP model will likely be LightGCN.

The Oversmoothing Problem

Layer 1: Each node knows its 1-hop neighbors Layer 2: Each node knows its 2-hop neighborhood Layer 3: Representations start converging Layer 5+: All nodes look nearly identical!

More layers ≠ better. For recommendation, 2–3 layers is typically optimal.

This is a valid experiment for your BTP: "How does GNN depth affect recommendation quality?"

Phase 8

Recommendation-Specific GNNs

Week 5–6 — Where your BTP specializes

★★★★★

Why Generic GNNs Aren't Enough

Standard GCN was designed for node classification:

  • Uses non-linear activations → not needed for CF
  • Uses feature transformation → recommendation has no initial features
  • Designed for homogeneous graphs → recommendation is bipartite

We need architectures designed for the recommendation task.

NGCF

Neural Graph Collaborative Filtering (Wang et al., 2019)

User / Item ID │ ▼ Embedding layer │ ▼ GNN propagation (with feature transform + nonlinearity) │ ▼ Layer concatenation │ ▼ Prediction

First major paper applying GNNs to collaborative filtering on user-item graphs.

LightGCN

He et al., 2020 — The star of your BTP ★

Key discovery: The feature transformation and non-linear activation in GCN/NGCF are not useful — even harmful — for collaborative filtering.

LightGCN strips them away, keeping only neighborhood aggregation.

LightGCN Architecture

User ──── Item │ │ └─────┬─────┘ │ ▼ Light Graph Convolution (no W, no σ) Layer 0: eu(0) (initial embedding) Layer 1: eu(1) = Σ 1/√(|Nu|·|Ni|) · ei(0) Layer 2: eu(2) = Σ 1/√(|Nu|·|Ni|) · ei(1) │ ▼ Layer Combination eu = (eu(0) + eu(1) + eu(2)) / 3 │ ▼ Score = euT · ei

LightGCN — What to Understand

  • User-item bipartite graph — the graph structure
  • Embedding propagation — only symmetric normalization, no weights
  • Layer aggregation — average embeddings across all layers
  • BPR loss — pairwise ranking optimization
  • Negative sampling — creating training signal from implicit feedback

This should be your central model and probably your most-cited paper.

NGCF vs LightGCN

Phase 9

Training & BPR Loss

Week 6 — How to train your recommender

Explicit vs Implicit Feedback

Explicit

User gives a rating

User → Movie: ★★★★☆ Predict: rating = 4.73

Sparse, not always available

Implicit

User interacts (click, buy, watch)

User → Movie: watched ✓ Predict: will user watch? 0/1

Abundant, more practical

Most modern RecSys (including yours) uses implicit feedback.

BPR — Bayesian Personalized Ranking

Instead of predicting a score, learn relative preferences:

User U Positive: Movie A (interacted) Negative: Movie B (not interacted) We want: ŷu,A > ŷu,B

BPR Loss

\( \mathcal{L}_{BPR} = -\sum_{(u,i,j)} \ln \sigma\!\left(\hat{y}_{ui} - \hat{y}_{uj}\right) \)

\(u\) = user

\(i\) = positive item (interacted)

\(j\) = negative item (sampled, not interacted)

\(\sigma\) = sigmoid function

Pushes positive items' scores above negative items' scores.

Negative Sampling

For each (user, positive_item) pair, we sample negative items:

User 1 interacted with: {A, C, E} Positive sample: (User 1, Movie A) Negative sample: (User 1, Movie B) ← randomly sampled from items NOT in {A, C, E}

Simple uniform sampling works. Some papers explore harder negatives.

Training Pipeline

1. Initialize user & item embeddings randomly │ ▼ 2. For each epoch: │ Sample (user, pos_item, neg_item) triplets │ │ │ ▼ │ Forward pass: GNN propagation → embeddings │ │ │ ▼ │ Compute BPR loss │ │ │ ▼ │ Backward pass: update embeddings │ └── Repeat │ ▼ 3. Evaluate with ranking metrics

Phase 11

Evaluation Metrics

Week 7–8 — One of the most important parts of your thesis

Recommendation is a Ranking Problem

Don't evaluate only with accuracy or MSE.

Your model outputs a ranked list of items for each user.

K = 10 Model recommends: [A, B, C, D, E, F, G, H, I, J] Actual relevant: {A, D, H} How good was the ranking?

Key Metrics

Precision@K = relevant items in top-K / K

Recall@K = relevant items in top-K / total relevant items

Hit Rate@K = 1 if any relevant item in top-K, else 0

NDCG@K = Normalized Discounted Cumulative Gain
— rewards relevant items ranked higher

MAP = Mean Average Precision

NDCG@K Deep Dive

Recommended list: [A, B, C, D, E, F, G, H, I, J]

\( \text{DCG@K} = \sum_{k=1}^{K} \frac{rel_k}{\log_2(k+1)} \)
